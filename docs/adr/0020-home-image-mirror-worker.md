# 0020 홈서버에서 상품 이미지 미러링 실행

- 상태: 채택 — 운영 적용 및 전환·복귀 검증은 후속 배포에서 판정
- 날짜: 2026-11-22

## 배경

상품 카드는 저장 즉시 사용할 수 있고, 썸네일을 기다리는 동안 원본 이미지나 대체 아이콘으로 표시할 수 있습니다. Cloud Run 백업은 요청 기반 CPU와 최소 인스턴스 0으로 운영하므로, 백업이 요청을 받는 동안에만 실행 기회가 있습니다. 초기에는 홈서버의 일시 종료보다 원본 URL의 유효 기간이 긴 경우가 많을 것으로 보고, 전환 중 썸네일 완료가 늦어지는 것을 허용합니다. 원본 URL의 실제 유효 기간과 적체 규모는 운영에서 확인할 가정입니다. [JEC-93](https://linear.app/ject5-team6/issue/JEC-93)

## 결정

- [ADR 0017](0017-product-image-storage-and-thumbnail-policy.md)의 미러링 대상 카드와 `PENDING` 작업을 홈서버와 Cloud Run 모두 같은 DB 트랜잭션에 저장합니다. 작업 저장과 실행은 별도 설정으로 제어합니다.
- 홈서버만 커밋 후 실행 및 주기 폴링을 합니다. 재기동 시 처리 가능 작업과 잠금이 만료된 작업을 기존 우선순위와 배치 한도로 이어서 처리합니다. Infra가 두 origin의 워커 실행 값을 지정합니다.
- 앱은 썸네일, 원본 이미지, 아이콘 순으로 표시합니다. 지정 아이콘이 없으면 앱 공통 아이콘을 사용합니다. 장애 전환 동안 추가 대기 또는 재시도를 사용자에게 요구하지 않습니다.

## 대안

- Supabase Cron으로 Edge Function을 호출하면 홈서버와 독립적으로 처리할 수 있습니다. Java WebP 변환과 외부 이미지 요청 제어의 이식 및 실행 한도 검증이 필요합니다.
- Cloud Run에서 요청 없이 실행하려면 상시 CPU와 인스턴스 유지 또는 별도 실행 주체가 필요합니다. 초기에는 카드 저장과 표시가 가능하고 복귀 후 처리할 수 있어 이 운영 비용을 들일 필요가 낮습니다.

## 영향과 한계

Cloud Run 전환 중 기록한 작업의 완료는 홈서버 복귀 시각과 대기열에 의존합니다. [ADR 0017](0017-product-image-storage-and-thumbnail-policy.md)의 저장 후 5초 목표는 홈서버가 실행 중인 구간에 적용합니다. 복귀 전에 원본이 만료되면 작업이 실패할 수 있고 카드의 아이콘 표시는 유지됩니다.

[운영 문서](../operations.md#장애-전환-시-미러링과-복귀-확인)에 따라 첫 전환과 복귀를 관측합니다. 복귀 후 처리 가능 작업의 적체가 반복되거나 전환 중 원본 만료로 썸네일 실패가 누적되면 독립 실행을 다시 평가합니다. 만료 데이터 정리의 실행 기한은 별도로 결정합니다.
