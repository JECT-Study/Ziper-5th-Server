# ADR 0002: 향후 장애 전환과 비밀 번들

- 상태: 대체됨(0004) — [ADR 0004](0004-deployment-and-failover.md)가 origin 구성, 운영값, KV 미사용과 배포 절차를 확정; 인프라 구현·프로비저닝·IAM 적용은 미실시
- 날짜: 2026-11-01

## 배경

여러 origin에서 같은 장애 상태와 설정을 사용해야 합니다. 무료 한도와 비밀 버전 교체 비용은 전체 계정 사용량과 운영 방식에 따라 달라집니다.

## 결정

향후 Worker의 SQLite Durable Object가 `CLOSED`·`OPEN`·`HALF_OPEN`의 권위 있는 상태를 소유합니다. KV는 설정 전용이며 장애 카운터·상태 전이에 사용하지 않습니다. 업무 4xx는 회로 판단에서 제외하고 결과가 불명확한 POST 등 쓰기를 재전송하지 않습니다. 공용 DB 장애는 두 origin에 영향을 줍니다.

Secret Manager의 고정 버전 JSON 번들을 향후 사용자 정의 `ConfigDataLoader`가 부팅 시 한 번 읽습니다. 표준 `sm@`는 원문 문자열을 읽는 것으로 JSON 속성 펼침이나 속성별 캐시를 보장하지 않습니다. 핫 리로드하지 않고 두 origin의 재시작을 조율합니다. 개발자는 개인 ADC를 사용하고 공유 서비스 계정 JSON을 배포하지 않습니다.

기존 secret을 다루는 개발자는 accessor와 versionManager를 사용하고 런타임은 accessor만 사용합니다. 최초 secret 생성은 별도 관리자 작업입니다. 정상 5개와 교체 중 1개 버전의 예산을 두고 발행을 직렬화합니다. 새 버전 검증 후 이전 버전을 destroy할 때 이전 버전으로 되돌릴 수 없다는 절충을 명시합니다.

## 영향과 미정 사항

[인프라 계획](../infrastructure.md)에 한도·비용·미정 운영값을 유지합니다. 창 크기·최소 표본·실패 임계치·회복 조건·한도 소진 시 동작은 배포 전에 후속 결정이 필요합니다. 전체 무료 운영을 보장하지 않습니다. Worker·GCP 코드나 리소스 생성은 이 결정에 포함하지 않습니다.
