# 0009 이메일 인증번호 발송과 검증 경계

- 상태: 대체됨(0012); 요청 한도와 오입력 제한은 [0012](0012-email-verification-lockout.md)가 대체하며 나머지 발송·검증 경계는 0012에서 유지
- 날짜: 2026-11-14

## 배경

가입 전에는 사용자 행이 없지만 이메일 인증번호를 발급하고 확인해야 한다. 발송은 PostgreSQL과 외부 SMTP에 걸친 쓰기이며 중복 발송과 무제한 번호 추측을 막아야 한다.

## 결정

기존 `ziper.auth_codes`에 별도 `flow_id`로 첫 발급과 재전송을 묶는다. 6자리 번호의 원문은 보관하지 않고 별도 키의 HMAC 해시와 3분 만료 시각을 저장한다. 같은 이메일은 3분 간격·시간당 5회, 같은 연결 출처는 시간당 20회로 제한한다. DB 트랜잭션 안에서 advisory lock과 기록을 사용해 인스턴스 간 제한을 공유한다.

재전송은 같은 `flow_id`에 새 행을 추가하고 이전 번호를 무효화한다. 틀린 입력은 흐름 전체에서 합산해 다섯 번째부터 추가 확인과 재전송을 막는다. 성공 시 최신 행에 검증 시각을 기록하며 회원 가입과 코드 소비는 후속 작업이다. 공개 상태 API는 실패·남은 횟수와 최신 만료 시각·남은 초를 DB 기준으로 반환한다. 화면 타이머·모달·이동은 클라이언트가 담당하며 서버의 만료·횟수 판정이 최종 결과다.

DB 기록을 먼저 커밋한 뒤 Spring Mail로 동기 발송한다. SMTP 결과가 불명확한 쓰기는 자동 재시도하지 않으며 오류는 전역 5xx 처리에 맡긴다. 기능은 기본 비활성이고 SMTP 자격과 HMAC 키는 런타임 환경에서 공급한다.

## 대안

- `users`에 번호를 저장: 가입 전 사용자 행이 없으므로 선택하지 않는다.
- 프로세스 메모리에 횟수·번호 저장: 재시작·다중 인스턴스에서 상태가 사라지므로 선택하지 않는다.
- SMTP 실패를 자동 재발송: 수신 여부가 불명확할 수 있어 선택하지 않는다.

## 영향과 한계

SMTP 실패 후에도 발급 행이 남아 재요청 제한이 적용된다. 프록시가 여러 사용자를 하나의 원격 주소로 전달하면 출처별 한도를 공유한다. 로컬 Gmail 발송·수신과 DB 기록은 확인했으며, 실제 수신 번호 입력과 운영 비밀 공급은 별도 E2E 검증이 필요하다.
