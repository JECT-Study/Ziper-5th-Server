# ADR 0001: 공통 실행·오류·아티팩트 경계

- 상태: 승인; 구현 상태와 검사 증거는 해당 PR 및 검증 이력으로 확인
- 날짜: 2026-11-01

## 배경

웹과 모바일이 같은 무상태 API를 사용합니다. 인증 실패와 업무 오류에 같은 공개 계약이 필요하고, Sentry 소스 문맥은 배포한 바이너리와 일치해야 합니다.

## 결정

공개 오류는 `ProblemDetail`의 `status`, `detail`, `code`, `requestId`로 표현합니다. `detail`은 정적인 한국어 카탈로그에서 선택하고 SQL·예외 메시지를 노출하지 않습니다. 서버가 요청 ID를 생성하며 JWT 401·403도 동일한 오류 팩토리를 사용합니다. 예상 업무 4xx만 `BusinessException`으로 표현합니다. 기술 예외는 업무 계층에서 삼키거나 업무 예외로 감싸지 않고 전역 경계에서 5xx로 처리합니다. 예상 4xx는 Sentry에서 제외하고 예상하지 못한 5xx는 요청당 한 번, 요청 ID와 연결합니다.

서버는 세션 없이 Bearer JWT를 검증합니다. Swagger는 생성 계약으로 유지하되 기본값과 서버 환경에서는 비활성입니다. 활성 프로필이 `local` 하나뿐이고 `APP_RUNTIME_MODE=local`, `SWAGGER_ENABLED=true`를 함께 선택한 경우만 노출합니다.

소스 업로드 시 만든 JAR를 재컴파일하지 않고 이미지에 넣습니다. 두 origin은 같은 이미지·설정 버전·JWT 설정을 사용합니다. 배포 아티팩트에 JAR·소스 번들·릴리스 식별자를 함께 보관합니다.

## 영향

업무 기능은 PR의 사용자 이야기와 E2E 증거로 설명합니다. 영구 문서는 공통 경계만 유지합니다. 오류 계약·인증 방식·아티팩트 생성 경로 변경은 후속 ADR이 필요합니다. 업로드한 소스와 다른 재빌드 이미지는 같은 릴리스로 배포할 수 없습니다.
