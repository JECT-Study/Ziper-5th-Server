# 0012 이메일 단위 인증번호 오입력 잠금

- 상태: 채택; 실제 메일 수신 번호 입력과 운영 배포는 미검증
- 날짜: 2026-11-14

## 배경

[ADR 0009](0009-email-verification-delivery.md)는 오입력 5회 제한을 인증 흐름(`flow_id`) 단위로 적용했다. 같은 이메일로 새 흐름을 시작하면 횟수가 초기화되어, 3분 간격과 이메일당 시간당 5회 발송 한도 안에서 한 이메일에 시간당 최대 25번까지 번호를 입력할 수 있었다. 기획 조건은 계정(이메일)당 최대 5회, 5회 실패 시 30분 뒤 같은 이메일로 재시도 가능(횟수 초기화)이다. 기존 이메일당 시간당 5회 발송 한도를 유지하면 30분 잠금이 끝난 뒤에도 지난 1시간의 발송 횟수 때문에 최대 약 1시간까지 재시도가 막혀 기획 조건과 충돌한다.

## 결정

오입력 횟수를 이메일 단위로 `ziper.email_verification_failures`에 합산한다. 5회째 오입력에서 30분 잠금 시각을 기록하고, 잠금 동안 같은 이메일의 발급·재전송·확인을 모두 `EMAIL_CODE_ATTEMPTS_EXCEEDED`(429)로 거부한다. 잠금 시각이 지나면 횟수를 0으로 본다. 잠기지 않은 실패 기록도 마지막 실패 후 30분이 지나면 0으로 본다. 인증에 성공하면 해당 이메일의 실패 기록을 삭제한다. 상태 API는 이메일 단위 실패·남은 횟수와 잠금 해제 시각(`lockedUntil`)을 반환한다.

이메일당 시간당 5회 발송 한도는 제거한다. 번호 추측은 이메일 단위 5회 잠금으로 막고, 메일 남용은 같은 이메일 3분 간격과 같은 연결 출처 시간당 20회 한도로 제한한다. 잠금 판정과 갱신은 ADR 0009와 같은 이메일 advisory lock 안에서 수행해 인스턴스 간에 공유한다. 번호 해시·3분 만료·DB 선기록 후 동기 발송·SMTP 자동 재시도 금지 등 ADR 0009의 나머지 결정은 그대로 유지한다.

## 대안

- 흐름 단위 제한 유지: 새 흐름마다 횟수가 초기화되어 기획의 계정당 5회 조건을 만족하지 못한다.
- `auth_codes`의 실패 횟수 합계로 계산: 실패 시각이 없어 30분 경과 여부를 판단할 수 없다.
- 이메일당 발송 한도를 30분당 5회로 축소: 잠금 해제 시점과 대체로 맞지만 잠금 없이도 발송이 막히는 경우가 남아 정책이 복잡해진다.
- 시간당 5회 발송 한도 유지: 30분 뒤 재시도 조건과 충돌한다.

## 영향과 한계

같은 이메일을 다른 사람이 5번 틀리면 이메일 소유자도 30분 동안 인증할 수 없다. 이메일당 발송 한도를 없애 같은 이메일로 3분마다 메일을 받을 수 있으며 출처별 한도는 프록시 뒤 사용자들이 공유한다. 잠금 동안의 응답은 남은 시간을 오류 본문에 담지 않으므로 클라이언트는 상태 API의 `lockedUntil`을 사용한다.
