# 0022 보드 상품 연결 소프트 삭제와 휴지통 지정 복구

- 상태: 채택 — V13 마이그레이션과 복구 API 반영
- 날짜: 2026-11-28

## 배경

[ADR 0015](0015-product-card-and-rediscovery-schema.md)는 사용자별 동일 URL 상품을 카드 한 행으로 저장하고 여러 보드에 연결한다. 당시 보드에서 상품을 제거하거나 보드를 삭제하면 연결 행을 물리 삭제하도록 정했다. 휴지통 복구 시 사용자는 현재 보유한 활성 보드 중 원하는 보드를 다시 선택해야 한다. 연결 해제의 상태도 영구 삭제와 구분해 보존할 필요가 있다.

## 결정

- `product_board_card`에 `is_deleted`와 `deleted_at`을 추가한다. 기존 행은 활성으로 유지하고, 보드에서 상품을 제거하거나 보드 자체를 삭제하면 활성 연결만 소프트 삭제한다. 같은 `(board_id, card_id)`의 고유 제약은 유지한다.
- 보드 목록·상세·홈 요약은 활성 연결만 집계한다. 보드 제거로 마지막 활성 연결이 사라진 카드만 상품 단위로 소프트 삭제해 휴지통에 한 번 노출한다. 상품 상세의 전체 삭제는 모든 활성 연결을 소프트 삭제한 뒤 카드를 소프트 삭제한다.
- 복구 화면은 삭제 후 30일 미만인 본인 카드에 대해 현재 보유한 활성 보드를 반환한다. 사용자가 1개 이상 선택하면 선택한 보드의 삭제 연결을 재활성화하거나 새 연결을 삽입한다. 선택하지 않은 연결은 비활성 상태로 둔다. 재활성화된 연결의 `created_at`은 다시 추가된 시각으로 갱신한다. 카드는 구매 예정·최초 14일 재발견 주기로 초기화한다.
- 쓰기는 `board:{userId}` 다음 `product-card:{userId}` 잠금 아래에서 검증하고 한 트랜잭션으로 처리한다. 보드 목록 조회 후 복구 요청에서도 선택한 보드와 카드 유효성을 다시 확인한다.
- 휴지통 즉시 영구 삭제는 `DELETE /api/v1/trash/products`의 `productIds` 배열 하나로 단일·다중 선택을 처리한다. 한 트랜잭션에서 전체 소유권·삭제 상태를 먼저 검증하고 하나라도 유효하지 않으면 전체를 거절한다. DB 외래 키의 `ON DELETE CASCADE`로 활성·삭제된 연결과 카드 하위 행을 제거한다.

## 대안

- 연결 행 물리 삭제 유지: 보드 해제와 카드 영구 삭제의 데이터 상태를 구분하지 못한다.
- 보드마다 상품 카드 복제: 동일 URL 상품이 휴지통에 중복되고 상품 상태 동기화가 복잡해진다.
- 복구 시 과거 보드 자동 재연결: 사용자가 현재 보유한 보드를 직접 선택하는 요구와 맞지 않는다.

## 영향과 한계

- V13은 컬럼을 추가하며 기존 연결은 활성 상태로 남긴다. 이전 버전에서 이미 물리 삭제된 연결은 복구할 수 없다.
- 현재 활성 보드가 0개면 빈 목록을 반환하고 복구 요청은 1개 이상을 요구한다. 이 화면에서 새 보드 생성이나 삭제된 보드 복구는 제공하지 않는다.
- 30일 만료 카드는 배치가 실행되기 전이라도 복구 후보 조회와 복구 요청에서 제외한다.
